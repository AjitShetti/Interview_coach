Welcome to the system design portion of the interview. Today we'd like you to design a highly scalable URL shortening service similar to bit.ly.

Let's start by defining the core requirements. What do you think are the functional and non-functional requirements for this system?
Okay, for functional requirements:
  • Given a long URL, generate a shorter alias.
  • When users click the short URL, redirect them to the original long URL.
  • Custom short links should be supported.

Non-functional:
  • High availability.
  • URL redirection should happen in real-time with minimal latency.
